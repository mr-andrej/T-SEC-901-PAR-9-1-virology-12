# s0P0wn3d - Architecture

## Overview

Classic implant/controller C2 design, built from scratch.

```
+----------------+        TCP (TLS from v0.2)        +------------------+
|   Windows VM   |  <==============================  | Operator machine |
|                |   reverse connection (implant     |                  |
|  implant.exe   |   dials out - NAT-friendly)       |  s0p0wn3d.py     |
|  (C, Win32)    |                                   |  (Python 3)      |
+----------------+                                   +------------------+
```

The **implant** initiates the connection (reverse shell). This is the
standard reason C2 implants dial out rather than listen: outbound traffic
crosses NAT and most perimeter firewalls, and no listening port appears on
the target (`netstat` shows an *established outbound* connection, which is
far less suspicious than a new listener).

## Components

### Implant (`implant/implant.c`, `implant/tls_schannel.c`)

- Pure C against Win32 + WinSock2 + SChannel, no external dependencies,
  compiles to a small standalone PE.
- v0.2: connect-back loop → TLS handshake (SChannel) with the controller
  certificate pinned by SHA-256 → spawn `cmd.exe` on anonymous pipes →
  single-threaded event loop shuttling framed, encrypted traffic.
- Single-threaded by design: SSPI contexts are not thread-safe, and one
  poll loop (PeekNamedPipe + select) draws less attention than threads.
- v0.1 (git history): raw TCP, cmd.exe std handles bound to the socket.

### Controller (`controller/s0p0wn3d.py`)

- Python 3 stdlib only (`ssl`, `socket`, `struct`, `threading`).
- v0.2: TLS listener, length-prefixed framing, multi-session REPL
  (`sessions` / `use <id>` / `back` / `kill <id>`), per-session reader
  threads with backlog buffering for detached sessions.
- Later iterations: command routing, pluggable command modules
  (`keylog`, `loot`, ...).

## Protocol

| Version | Transport | Framing | Crypto | Status |
|---------|-----------|---------|--------|--------|
| v0.1    | raw TCP   | none (timeout-drained stream) | none | superseded |
| v0.2    | TCP       | length-prefixed (4-byte BE) | TLS (SChannel/OpenSSL), server cert SHA-256-pinned in implant | **current** |
| v0.3+   | TCP or HTTP(S)/DNS tunnel | tasking model (beacon + jitter) | TLS + per-session keys | planned |

Certificates are generated by `tools/make_certs.sh`: a local CA signs the
controller cert; the script also emits `implant/cert_pin.h` with the
SHA-256 fingerprint the implant pins. Cert rotation = re-run + rebuild.

## Roadmap / known-weakness resolution order

1. **v0.1 "brut"** - done. Raw reverse shell. Deliberately noisy:
   plaintext, hardcoded C2, spawns `cmd.exe`. Purpose: working channel for
   the first follow-up.
2. **v0.2** - done. TLS with cert pinning (prove encryption in Wireshark:
   v0.1 shows readable plaintext, v0.2 shows `Application Data` only),
   proper message framing, multi-session controller.
3. **v0.3** - persistence (registry Run key, then a stealthier method),
   restart-on-kill (watchdog), built-in shell commands to avoid spawning
   `cmd.exe` (reduces Sysmon process-creation telemetry), config-file C2.
4. **v0.4+** - extended commands (loot, keylog, privesc, ...), each mapped
   in `docs/MITRE.md`, log rollback/cover-tracks, AV evasion work against
   the declared lab AV.

## Defender's view (detection surface, current state)

| Weakness | Detection | Status |
|----------|-----------|--------|
| Plaintext shell traffic | Any IDS sees command/output strings on port 4444 | fixed in v0.2 (TLS) |
| Hardcoded IP/port | Static IOC, extractable with `strings` | open, v0.3 config |
| `cmd.exe` child process | Sysmon Event ID 1, unusual parent-child pair | open, v0.3 built-ins |
| Fixed 5 s reconnect | Beaconing pattern in NetFlow, constant interval | open, jitter later |
| TLS on odd port, self-signed, no SNI | JA3/JA4 fingerprinting, cert inspection | open, tunnel milestone |

Each of these is an intentional teaching point: the blue-team notes in
`docs/MITRE.md` explain how a SOC catches v0.1, and each later iteration
removes exactly one detection surface.
